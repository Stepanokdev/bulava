ЗВІТ ПРО РЕЗУЛЬТАТ (обовʼязково, коли робота реально зроблена — не заглушка):
ОДИН документ, який користувач відкриває кнопкою. Усе — у ньому. Поклади все СЮДИ (створи теку): {{DIR}}{{CONTINUING}}

1) Напиши маніфест {{DIR}}/report.json (шляхи до ассетів — ВІДНОСНІ, файли поруч у тій самій теці):
   {"format":"photos"|"video"|"notes","language":"{{LANG}}","title":"…",
    "summary":"1–3 речення: що змінилось",
    "attention":["що саме потребує рішення користувача"],   // опційно; пусто, якщо нічого не потрібно
    "sections":[                                          // ГОЛОВНЕ: відповідь на КОЖЕН його пункт
      {"ref":"5","title":"PDF, Word і копіювання","status":"закрито",
       "body":"Було … Стало … (а якщо кадру немає — чому саме немає)",
       "items":[{"caption":"…","before":"before-2.png","after":"after-2.png"}]}],
    "body":"решта звіту у вільній формі: як перевіряли, знайдені по дорозі речі, таблиці, деталі",
    "items":[…], "video":"demo.mp4"}   // кадри/відео, що не належать конкретному пункту
   Текст (title / summary / sections / body / caption / attention) — мовою {{LANG}}.
2) СТРУКТУРА, якої чекає користувач — по його пунктах, а не по нашому плану:
   «1. Закрили, ось доказ (скріншоти). 2. Закрито, але тут скріншоти неможливі — бо це вивантажений
   файл / бо дефект не відтворився. 3. Не закрито, бо бекенд не готовий.»
   Тому: якщо в задачі є блок «ЩО ПРОСИВ ДИРЕКТОР, ЙОГО СЛОВАМИ І ЙОГО НУМЕРАЦІЄЮ» — `sections` іде
   САМЕ по тому списку, у тому ж порядку і з тими ж номерами (`ref`), навіть якщо наш план згрупував
   їх інакше. Жоден його пункт не має зникнути: якщо по пункту нічого не робили — це теж відповідь
   («не закрито», «не застосовується»), з причиною. `status`: закрито / частково / не закрито /
   заблоковано / не застосовується. Доказ для пункту кладеться В ЦЕЙ ЖЕ розділ (`items`), а не в
   спільну галерею в кінці — і якщо кадру немає, скажи ОДНИМ реченням, чому.
3) НЕ винось зміст у сусідній файл. Рядок «повний звіт у NOTES.md поруч» — це незданий звіт.
   Логи, таблиці, вивантаження можна класти файлами поруч, але сам зміст має бути в звіті.
   `body` і `sections[].body` — markdown: заголовки (##), списки, таблиці, ``` для коду.
   `body` — це решта розповіді (як перевіряли, що знайшли по дорозі, деталі); без `sections` він
   лишається основним текстом звіту і заповнюється завжди.
4) Докази. Обери САМ, за характером зміни (можна поєднувати):
   • статична/візуальна зміна (екран, лейаут, кольори, копірайт, стан UI) → кадри ДО/ПІСЛЯ;
   • інтерактив / анімація / новий флоу / нова поведінка → коротке відео (10–30 с);
   • невізуальна зміна (бекенд, логіка, API, рефактор, конфіг, дані, тести) → без кадрів, лише текст.
   Підписи до кадрів прив'язуй до пунктів задачі («крок 4», «AC-017»), щоб було видно, що чим доведено.
5) Як знімати РЕАЛЬНИЙ застосунок:
   • Web: у тебе Є браузер, командами рушія — MCP не потрібен і дозволів не просить:
     `$IDIR/web-shot <url> <out.png> [ширина] [висота] [--full] [--wait c]` — кадр сторінки;
     `$IDIR/web-video <url> <out.mp4> [секунд] [ширина] [висота]` — короткий запис.
     Обидві ганяють Chrome у headless і віддають пікселі через DevTools-протокол. Якщо потрібен
     логін — підніми локальну збірку і знімай її, або скажи у звіті, чого саме не вийшло.
   • iOS: xcrun simctl boot <device> → встанови зібраний .app → `xcrun simctl io booted screenshot f.png`
     для кадрів, або `xcrun simctl io booted recordVideo demo.mp4` (зупини після флоу). Можна через appium.
   • macOS-застосунок: ЛИШЕ `$IDIR/capture out.png --window <pid>` (або без --window — весь екран).
     `screencapture` під tmux не має дозволу на запис екрана і завжди падає — кадру не буде.
     Якщо capture не спрацював, напиши це в summary; НЕ підставляй заглушку замість кадру.
   • Android: `adb exec-out screencap -p > f.png` або `adb shell screenrecord`.
6) Для ДО/ПІСЛЯ зніми стан ДО зміни (за потреби тимчасово повернись на базовий стан/гілку і збери),
   потім ПІСЛЯ. Якщо «до» технічно не зняти — постав after-only кадри або відео і чесно зазнач це в summary.
Реальні кадри/відео справжнього застосунку. Якщо зняти неможливо — коротко напиши в summary чому,
і поклади хоча б наявні артефакти. Це частина визначення «готово».
7) НАОСТАНОК, коли маніфест і кадри готові, збери АРТЕФАКТ — одна команда, без аргументів:
       $IDIR/artifact
   Вона складе з маніфесту й кадрів самодостатню сторінку в самому проєкті:
   `artifacts/<дата>-<назва>/index.html` (+ `artifacts/latest`), і додасть `artifacts/` у .gitignore.
   Це те, що користувач відкриває подвійним кліком — без застосунку, без сервера. Виклич її ОДИН раз,
   після того як маніфест повний: якщо потім щось у звіті виправив — виклич ще раз, вона перезбере.
   Шлях, який вона напише, згадай у своєму фінальному повідомленні.
